# Yacht Dice

같은 내부망에서 2~4명이 플레이하는 요트 다이스입니다. 중앙 서버가 방 생성·참가·준비, 주사위와 점수, 재접속과 승패를 관리합니다. WebRTC나 coturn은 필요하지 않습니다.

## 내부망 서버 실행

별도로 전달받은 이미지 tar는 `docker load -i <이미지 파일.tar>`로 불러옵니다. 이미지 태그는 `yacht-dice:local`입니다. 체크섬 파일을 함께 받았다면 전송 무결성을 확인할 수 있습니다.

Docker로 실행하려면 `yacht_dice` 폴더에서 `docker compose up -d --build`를 실행합니다.

```powershell
npm.cmd ci
npm.cmd run build
npm.cmd start
```

서버 컴퓨터에서는 `http://localhost:3000`, 다른 기기에서는 서버가 출력하는 `http://내부-IP:3000`으로 접속합니다. 여러 주소가 출력되면 실제 Wi-Fi 또는 유선 LAN 주소를 선택하세요. 터미널의 Ctrl+C로 종료합니다. 한 사람이 최대 인원 2/3/4명과 재접속 대기 시간을 설정해 방을 만들고 초대 링크 또는 코드를 전달합니다. **현재 참가자가 2명 이상이며 모두 연결·준비 상태이면 정원 미달이어도 시작합니다.** 더 기다리려면 준비를 누르지 마세요. 시작 후 신규 참가는 불가능합니다.

필요하면 `.env.example`을 `.env`로 복사해 수정하고 서버를 재시작합니다. `HOST` 기본값은 `0.0.0.0`, `PORT`는 `3000`, `DISCONNECT_GRACE_SECONDS`는 `60`이며 재접속 대기는 1~86400초 정수입니다.

접속이 안 되면 같은 LAN인지, 서버 IP가 맞는지, 방화벽이 Node.js 또는 해당 TCP 포트를 허용하는지 확인하세요. 게스트 Wi-Fi의 기기 간 통신 차단도 확인합니다. 방화벽 전체 해제나 인터넷 포트 포워딩은 필요하지 않습니다. `/health`에서 서버 응답을 확인할 수 있습니다.

설치에는 패키지 다운로드가 필요하지만 빌드 후 플레이에는 외부 인터넷이 필요하지 않습니다. 인터넷 공개 배포는 첫 출시 범위가 아닙니다.

## 주사위 액션

증강 모드 점수판의 예상 숫자는 해당 칸에 기록할 점수입니다. 칸을 선택하면 기록 점수, 증강·사건 점수, 총점 변화를 따로 표시합니다. 다른 0점 칸 복구·상단 보너스·총점 하한 보정도 별도 항목입니다. 예상값은 실제 채점 처리의 상태 복제본으로 계산하며 원래 게임 상태를 변경하지 않습니다.

증강 선택창은 카드마다 한 번씩 리롤할 수 있고, 등급별 광채와 남은 횟수를 표시합니다. 일반 능력 중 수집가·스트레이트 장인·가짜 풀하우스·초이스 보너스는 각각 **중복은 못 참지**, **스트레이트 밀수업자**, **강제 룸메이트**, **이번 판은 현금으로**로 개편했습니다. 중복 눈 재굴림, 없는 숫자 밀수, 두 눈의 평균 배분, 빈 하단 칸 환전을 지원하며 정확한 횟수와 조건은 능력 도감에서 확인할 수 있습니다.

‘흔들기’를 누르면 컵에서 섞고, ‘던지기’를 누르면 쏟습니다. 스페이스바도 대기 중에는 흔들기를 시작하고 섞는 중에는 던집니다. 서버의 cannon-es가 실제로 멈춘 주사위의 윗면을 읽어 숫자를 확정합니다. 브라우저의 Three.js는 서버가 전송한 컵·주사위의 위치와 회전만 재생하므로 모두 같은 궤적과 최종 배치를 봅니다. 보관한 주사위는 컵과 물리 계산에서 제외하며, 보관을 해제하면 이전 자세가 복원됩니다.

마우스·터치로 컵을 움직이는 기능은 제거했습니다. 섞기 전에는 ‘던지기’가, 섞는 중에는 ‘흔들기’가 비활성화됩니다. 채팅 입력, 키 반복, 연결 중단 중에는 단축키가 작동하지 않습니다. 결과가 나온 뒤에는 컵을 다시 띄우지 않아 주사위를 가리지 않습니다. 컵 지름과 충돌 공간을 함께 키우고, 중력과 흔들기·쏟기 힘을 높였습니다. 섞는 동안 투명 덮개가 주사위의 이탈을 막고 쏟을 때 열립니다.

모든 주사위의 이동·회전이 0.6초 동안 잦아들었는데도 착지가 불완전하면 “바람이 불어온다~~”와 함께 8방향 중 무작위 방향으로 힘을 가합니다. 두 번째·세 번째 바람도 다시 멈추기를 기다리며, 더 강하게 주사위를 띄우고 회전시킵니다. 10초의 시뮬레이션 시간 안에 해결되지 않으면 이전 배치를 복원하며 굴림 횟수를 차감하지 않습니다. 과부하를 포함한 실제 대기 시간은 최대 20초로 제한합니다. 숫자나 최종 자세를 강제로 맞추지 않습니다.

윗면은 약 32도까지 기울어져도 분명하게 읽히면 인정하며, 0.3초간 정지 상태를 유지해야 확정합니다. 모서리로 서거나 높게 쌓인 경우는 계속 구조 바람 대상입니다. 트레이 앞뒤 깊이는 5에서 7로 넓혔으며 렌더링과 충돌 영역이 일치합니다.

서버는 CPU 수에 따라 최대 4개의 물리 작업 스레드를 사용합니다. 물리는 고정 1/480초 간격이며 초당 60개 자세를 3개씩 묶어 전송합니다. 클라이언트는 서버 시각을 보정하고 150ms 버퍼에서 재생합니다. 물리 프레임은 게임 revision을 변경하지 않습니다. 연결 중단 시 흔들기는 정지하고, 이미 쏟기 시작한 굴림은 완료 후 결과를 보관합니다. 재접속은 최신 자세에서 이어집니다. 모션 줄이기 설정은 정적인 결과를 표시하고, WebGL 미지원 환경도 아래 슬롯으로 플레이할 수 있습니다.

물리·통신 변경은 클라이언트와 서버를 함께 배포해야 합니다. npm test는 규칙, 서버 통신, 컵 충돌과 보관 격리, 클라이언트 재생을 검사합니다. node server/test/physics-load.mjs는 동시 10개 방·40명을 검사하고, node server/test/physics-audit.mjs 20500은 재현 가능한 난수 표본으로 면별·슬롯별·흔들기 시간별 빈도와 착지 실패를 기록합니다. 장시간 통계 검증은 일반 테스트와 분리하며 결과는 artifacts/server-physics/에 저장합니다.

이 버전은 통신 계약이 변경됐습니다. 업데이트 후 서버를 재시작하고 브라우저를 새로고침하세요. 재시작하면 기존 방은 복원되지 않습니다.

## 프로필 이미지

입장 화면에서 프리셋 6개 또는 PNG·JPEG·WebP 파일을 선택합니다. 파일은 최대 5 MiB·1600만 픽셀이고 브라우저가 중앙을 잘라 128×128 PNG(최대 96 KiB)로 재인코딩합니다. 원본 파일은 서버에 보내지 않습니다.

선택값은 해당 브라우저·접속 주소의 IndexedDB에 보관됩니다. 프리셋을 선택하면 저장된 업로드 선택값을 대체합니다. 저장소가 차단되면 안내를 표시하고 이번 접속에서 사용할 수 있습니다. 이미지는 대기실과 경기·결과의 점수표에 표시됩니다.

서버는 썸네일을 방 메모리에만 보관하고 같은 방 참가자에게 전달합니다. 이미지 파일·DB 저장은 하지 않으며 방 삭제·서버 종료 시 사라집니다. 재접속은 서버의 기존 프로필을 복원합니다. 프로필 변경은 입장 전에만 가능하고 중복 선택은 허용합니다. 업데이트 후 서버를 재시작하고 모든 브라우저를 새로고침하세요.

## 연결과 보관 정책

- 같은 탭의 새로고침과 일시적인 연결 끊김은 자동 복구합니다. 재접속 정보는 탭별 `sessionStorage`에 저장하며 탭을 닫은 뒤 복귀는 보장하지 않습니다.
- 서버가 끊김을 감지하면 방에 설정된 시간(1~86400초)을 기다립니다. 생성 화면에서 미입력하면 서버 환경변수 기본값(기본 60초)을 사용합니다. 연결 중 무행동에 대한 턴 제한은 아닙니다. 15초 간격 heartbeat 때문에 실제 단절보다 감지가 늦을 수 있습니다.
- 비기권 참가자의 재접속 대기 중에는 전체 경기를 멈춥니다. 대기 만료·자발적 퇴장은 해당 참가자의 기권이며 2명 이상 남으면 계속, 연결된 1명만 남으면 기권 승리입니다. 마지막 1명도 끊겨 있으면 복귀/만료를 기다리고 모두 기권하면 승자 없이 종료합니다.
- 무작위 선공 이후 자리순으로 진행합니다. 정상 완주는 24/36/48턴이며 최고점 동률은 공동 승자, 같은 점수는 공동 순위입니다. 기권자의 점수는 남지만 순위에는 포함되지 않습니다.
- 연결된 사람이 없는 대기실과 종료된 방은 30초 뒤 삭제합니다. 수신한 결과 화면은 남지만 삭제 후 재접속은 불가능합니다.
- 방은 메모리에만 저장하므로 서버 재시작 시 사라집니다. 내부망 HTTP는 암호화되지 않으므로 신뢰하는 네트워크에서만 실행하세요.

## 준비

- Node.js 22.12 이상
- npm

저장소 루트에서 의존성을 설치합니다.

```powershell
npm install
```

PowerShell의 실행 정책 때문에 `npm` 명령이 막히면 `npm.cmd install`을 사용합니다.

## 개발 실행

서로 다른 터미널에서 실행합니다.

```powershell
npm run dev:client
npm run dev:server
```

PowerShell에서 필요한 경우 `npm.cmd run dev:client`, `npm.cmd run dev:server`를 사용합니다. 클라이언트 주소는 Vite가 출력하며, 서버의 상태 확인 주소는 `http://127.0.0.1:3000/health`입니다. 서버 포트는 `PORT` 환경변수로 변경할 수 있습니다.

개발 클라이언트는 `/ws`를 3000 포트의 게임 서버로 전달합니다. 다른 기기에서 플레이할 때는 위의 프로덕션 빌드·단일 서버 실행 절차를 권장합니다.

## 확인

### 증강 모드 — 운명의 주사위

방 생성 시 일반/증강을 선택합니다. 현재 카드는 74종(일반 58종, 번뜩임 16종), 공용 사건은 8종입니다. 번뜩임은 플레이어별 선택 단계마다 10% 확률으로 한 장 등장하며 새로고침은 당첨 여부를 다시 추첨하지 않습니다. 기존 점수표를 유지하여 12라운드, 라지 스트레이트 30점이며 트리플 칸은 없습니다.

- 1·4·7·10라운드: 실버/골드/골드/프리즘 3택1. 선택할 때마다 카드 세 장을 각각 한 번씩 리롤할 수 있습니다. 누른 카드만 같은 등급의 다른 능력으로 바뀌고 나머지 두 장은 유지됩니다. 번뜩임 여부도 유지하며, 같은 선택 단계에서 이미 본 카드는 다시 나오지 않습니다. 재접속해도 사용한 리롤은 복구되지 않습니다. 7라운드에 손끝 보정을 가진 사람은 골드 선택 대신 현실 조작으로 교체할 수 있습니다. 진화하면 능력 개수는 증가하지 않습니다.
- 3·6·9·12라운드: 모든 사람에게 동일한 사건 적용. 플레이어 순서는 라운드가 바뀌어도 유지되어 차례대로 번갈아 진행합니다. 선택 중 연결이 끊기면 기존 재접속 대기/기권 규칙을 적용합니다.
- 증강 선택·사용·점수·공용 사건은 서버가 검증합니다. 실제 재굴림은 모두 서버 물리엔진으로 처리합니다. 보정 능력은 명시적인 눈 변경이며, 변경된 3D 방향·숫자·효과 기록을 동기화합니다.
- 추가 주사위 효과는 합산됩니다. 여섯 번째 주사위와 과잉 공급이 겹치면 7개 전체로 채점합니다. 5개 선택 과정 없이 상단·찬스·포카드·풀하우스의 합계에 모든 주사위를 포함합니다. 풀하우스는 서로 다른 눈의 3개 이상과 2개 이상(또는 같은 눈 5개 이상), 라지 스트레이트는 5연속 이상, 야추는 같은 눈 5개 이상이면 인정합니다.
- 상자 속 고양이는 첫 물리 굴림 상태로 돌아갑니다. 이미 소비한 증강 횟수·선언은 되돌리지 않습니다. 두 세계를 비교한 뒤 하나를 확정하며, 확정 후 일반 굴림은 끝납니다. 무료 재굴림도 고집불통의 해당 주사위 보관 연속성을 끊습니다.
- 왕의 압수수색/도플갱어는 증강 선택 단계에서 대상까지 확정합니다. 유효 대상이 없어지면 +10점으로 대체합니다. 교환 시 남은 횟수를 보존하고 동일 능력의 일반 중복 획득은 막습니다. 도플갱어는 예외이며 지속형 골드(매 턴 사용형 포함)를 복제할 수 있습니다.
- 적대 효과는 자기 차례에 다음 대상 턴을 예약합니다. 방패는 즉시 판정하고 공격 횟수는 소비됩니다. 예약 공격은 대상당 하나, 직접 점수 피해는 기본 개인 턴당 최대 10점입니다. 번뜩임 착불 폭탄은 20점, 악마의 택배 몸값은 30점 상한 예외입니다. 결투 중 빚내서 굴려로 2회 제한을 초과할 수 없습니다. 기권자가 포함된 미완료 결투는 취소됩니다.
- 지워진 0/평행 채점은 이번 점수 확정 전에 적용할 칸을 예약하고 일반 기록과 함께 원자적으로 처리합니다. 별도 턴·연속 성공·기생 효과를 재발동하지 않습니다. 평행 채점은 버림 처리합니다.
- 성적표 맞바꿔치기는 이미 기록한 같은 하단 칸의 값을 교환합니다. 피해 10점 상한과 별개인 교환이며, 상대당 한 번만 당하고 득점 효과·상단 보너스는 재발동하지 않습니다. 골드 대이동은 남은 사용 횟수와 사용 기록을 보존하고 중복 골드도 허용합니다. 빌린 골드는 이동 대상에서 제외됩니다.
- 방금 건 연습은 첫 굴림의 최고 눈 하나를 자동 물리 재투척합니다. 폭탄 주사위는 아래 슬롯에 표시하고, 악마의 택배로 봉인한 세 주사위는 평행세계 복원 후에도 1로 유지합니다. 첫 굴림에 걸린 방해는 먼저 해결한 뒤 평행 던지기를 사용할 수 있습니다.
- 지급·발동 내역에서 최근 40개 결과와 누적 증강 보너스를 확인합니다. +10점 대체 보상도 실제 지급 시점에 사유와 함께 표시하며, 지워진 0·평행 채점은 점수 확정 전까지 지급 예약으로 구분합니다. 재접속 시 내역은 유지하고 지난 알림은 재생하지 않습니다.
- 기본 족보 → 강화 → 배율(최대 ×3) → 별도 보너스/페널티 → 강탈 순서입니다. 도박 성공 판정은 강화 전 기본 점수입니다. 상단 보너스는 일반 규칙의 상단 점수만 누적하며, 악마의 계약 실패로 0점 처리된 칸은 적립하지 않습니다. 증강 보너스/페널티는 별도 행으로 표시합니다.

`shared/src/augments.ts`가 카드 정의, `shared/src/augment-game.ts`가 서버와 클라이언트에서 공유하는 효과·미리보기 규칙입니다. 카드 이미지는 외부 링크에 의존하지 않는 SVG 아이콘입니다. 기존 클라이언트와 통신 구조가 달라졌으므로 서버 업데이트 후 브라우저를 새로고침하세요.

추가 검증 명령:

```powershell
node --test shared/test/augments.test.mjs server/test/augment-network.test.mjs server/test/augment-physics.test.mjs
node scripts/augment-balance.mjs 10000
node scripts/flash-balance.mjs 2000
node --test server/test/flash-network.test.mjs
node scripts/check-augments.mjs
```

브라우저 검사는 Playwright와 Chrome이 필요합니다. 별도 설치 경로의 Playwright 모듈 URL을 첫 인수로 지정할 수도 있습니다. 결과는 `artifacts/augments/`에 저장됩니다. 자동 대전은 균등 난수와 휴리스틱 봇을 사용하는 스트레스/밸런스 참고 자료이며 물리 주사위의 공정성 또는 능력의 인과적 승률 기여도를 증명하지 않습니다.

`npm.cmd run format:client`로 클라이언트 코드를 정리하고, `npm.cmd run verify`로 포맷·타입·전체 테스트·빌드를 한 번에 확인할 수 있습니다. `npm.cmd run test:client`는 강조 판정, 화면, DOM 이벤트와 네트워크 유틸을 검증합니다.

자동 검증에는 2·3·4개 WebSocket 연결의 정상 완주, 정원 미달 시작, 방별 설정, 다인 기권·재접속, 네 프로필 수신·채팅, 공동 순위 및 기존 게임 조작 회귀 검증이 포함됩니다. 실제 브라우저·모바일·LAN 기기의 다인 화면 검수는 별도로 필요합니다. 업데이트는 현재 경기가 끝난 뒤 빌드→서버 재시작→모든 브라우저 새로고침 순서로 적용하세요. 메모리 방은 재시작 시 복원되지 않습니다.

```powershell
npm run typecheck
npm run test
npm run build
```

`shared/`는 점수 칸 ID, 공개 게임 상태, 클라이언트 명령, 서버 응답의 타입과 런타임 검증을 제공합니다. 예를 들어 서버는 받은 JSON 문자열을 `decodeClientMessage(raw)`로 검증할 수 있습니다. `roomState`에는 재접속 토큰을 넣을 수 없고, 토큰은 해당 플레이어에게만 보내는 `session` 메시지에 들어갑니다.
